## 后续：消息队列从 RabbitMQ 换为 RocketMQ 5.3.2（「换 MQ 不换架构」）

- **起因**：用户问「RocketMQ 原生延迟消息 `setDelayTimeLevel(16)`，到期后才发，能不能直接换一个消息队列」。评估后否定纯延迟消息方案：send 在下单时就发生（不是到期才发）、事务消息不支持延时消息、18 档是相对档位且本项目超时配置为 120 分钟（后台改 45/90/180 无解）、会废掉「固定 `expire_time` 不受配置变更影响」、裸用延迟消息没有扫描兜底和失败留痕。用户选定「换 MQ 不换架构」。
- **保留不动**：`oms_order_message` 三表与全部 DAO SQL、`OmsOrderMessageDispatcher`（租约 CAS/退避/SENT 语义）、`OmsOrderMessageService`、`OrderStateTransitionServiceImpl`（0→4 幂等）、下单事务与固定 expire_time、扫描兜底、指标告警、运维接口、`OrderCancelPublisher` 接口、A 的 32 个用例、所有迁移 SQL。**业务核心一行未改**。
- **只改适配层**：`pom.xml`（`rocketmq-client:5.3.2` 原生 SDK，绕开 starter 与 Spring Boot 3.5 的 javax/jakarta 争议）、`RocketMqTopics.java`、`RocketMqConfig.java`、`CancelOrderSender.java`（同步 send + `SEND_OK` / `No route info` / 非 OK / UNKNOWN）、`CancelOrderReceiver.java`（`MessageListenerConcurrently` 返回值即确认、固定延迟级别重试 topic、主动投 DLQ）、两份 yml、3 个 B 测试类 + 基类、compose + `rocketmq-broker.conf` + LOCAL.md。删除 `QueueEnum.java` / `RabbitMqConfig.java` / `OrderMessageEndToEndRabbitTest.java`。
