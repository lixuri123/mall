- 实测可用镜像站（`/v2/` 返回 401 且 `docker manifest inspect` 成功）：`https://docker.1ms.run`、`https://docker.m.daocloud.io`（`mysql:5.7` 与 `redis:7` 都能取到 manifest）；`docker.xuanyuan.me` 只有 mysql:5.7，redis:7 不可用。

- PowerShell 续行符是反引号而非 `\`；多行 `docker run` 建议写成单行，并给 `--xxx` 参数加引号，否则 PowerShell 会把行首 `--` 当成自减运算符报 ParserError。

## 3306 端口冲突（重要）
- 本机装有 **MySQL 8.0 Windows 服务 `MySQL80`**（`C:\Program Files\MySQL\MySQL Server 8.0\`，my.ini 在 `C:\ProgramData\MySQL\MySQL Server 8.0\my.ini`），开机自启、正在运行，绑定 IPv6 通配符 `::` 的 3306，`127.0.0.1:3306` 也可连通。Docker 想 bind `0.0.0.0:3306` 会报 `Only one usage of each socket address ...`。
- 排查要点：`Get-NetTCPConnection -LocalPort 3306 -State Listen` 查不到它（状态显示为 Bound），必须**不加 -State** 才能看到；`netstat -ano | findstr :3306` 也查不到。以后查端口占位别只查 Listen。
- 采用方案：**容器 MySQL 映射到宿主机 3307**，项目 jdbc 全部改为 `localhost:3307/mall`。已改动 4 个文件：`mall-admin`/`mall-portal`/`mall-search` 的 `application-dev.yml`，以及 `mall-demo` 的 `application.yml`。`application-prod.yml` 里的 `db:3306` 是容器内网，**不要改**；`docker-compose-env.yml` 的 `3306:3306` 也会和本机 MySQL80 冲突，走 compose 路线前需先处理。
- 备选方案：管理员 PowerShell `Stop-Service MySQL80`（或 `Set-Service MySQL80 -StartupType Manual`）让出 3306，则项目配置保持 3306 不变。
- `docker run` 端口绑定失败会留下状态为 `Created` 的容器，重跑前须 `docker rm -f mall-mysql`（命名卷、镜像都保留）。

## 最终采用的本地环境方案（document/docker/LOCAL.md）
- 项目新增 `document/docker/docker-compose-local.yml` + `document/docker/LOCAL.md`，用 `docker compose -f document/docker/docker-compose-local.yml up -d --build` 一次起 5 个容器，项目名 `mall-local`：mysql(3307:3306, root/root, 首次空卷自动导入 mall.sql)、redis、mongo、rabbitmq(/mall vhost + mall/mall)、elasticsearch 8.18.8（已装 analysis-ik 8.18.8）。实测 76 张表、Redis PONG、vhost/账号齐全。
- 构建命令：`& 'D:\Tools\apache-maven-3.9.9\bin\mvn.cmd' -B '-DskipTests' '-Ddocker.skip=true' package`；三条 `java -jar` 分别起 admin:8080 / portal:8085 / search:8081。jar 内配置须与源码一致（已确认打包进去的是 3307 + allowPublicKeyRetrieval=true）。
- 该 compose **不含 MinIO / Nginx / 日志采集**，admin 的 `endpoint: http://localhost:9000` 上传功能不可用，但不影响启动。
- 首次启动 search 后需 `POST http://localhost:8081/esProduct/importAll` 灌商品数据到 ES。
- 遗留：手工 `docker run` 留下的 `mall-mysql` 容器仍是 `Created` 状态（无害，可 `docker rm -f` 清掉）。
- PATH 里的 java 已切到 `D:\JAVA\jdk17\bin\java.exe` = 17.0.11，系统 JAVA_HOME 同；之前 1.8 的问题已解决。
